# ComplyDesk (working name) — working rules

Secretarial compliance for CS firms and in-house CS: Private Ltd + OPC (MVP). Same stack and patterns as VendorGate (rsambamurthy/VOB): React + Vite, Node/Express + TypeScript, Postgres + Drizzle, cookie sessions, permission-based roles.

## Reuse, never duplicate (standing rule)
Build once, use everywhere. Before writing a helper, component or rule, look for an existing one and extend it.

### Where the shared pieces live
- **Compliance rules are data**: built-ins in `server/src/compliance/catalogue.ts` (seeded to `rules`, tenant_id null); a workspace overrides by code (Administration → Compliance rules). Never hard-code a due date elsewhere.
- **Rule changes** only through `services/rules.ts` (shared validator `ruleInput`, Integrata's built-in rules, a firm's own versions and rules, history). Layers: catalogue.ts → Integrata (source PLATFORM; deploys don't overwrite) → workspace. UI: `components/RuleEditor.tsx` (editor, history, wording) on one `pages/admin/Rules.tsx` for both firm and platform. Documented in `docs/rules.md` and `components/RulesGuide.tsx` — keep both in step with the engine.
- **Engine** (pure, tested): `server/src/compliance/engine.ts` — `obligationsFor`, `nextKycFy`, `eventObligation`, `lateFeeEstimate`. Date helpers `compliance/dates.ts` (FY, first FY, AGM last date).
- **Sync**: `compliance/sync.ts` — `syncClient` / `syncTenant` store engine output; status/SRN/notes are never overwritten; nightly job `jobs.ts`.
- **Client master writes** only through `services/clients.ts` (routes and Excel import both use it). Every write re-syncs.
- **Obligations** read/update through `services/obligations.ts`; buckets (overdue/week/month/open/done) defined once in `bucketWhere`. Meeting → anchor linkage in `feedAnchors` (AGM held → AGM date; earliest board meeting → first BM date).
- **Field rules**: `server/src/lib/validators.ts` — screens and import share them.
- **Web**: `AppFrame`/`NavIcon`/`TabStrip`/`ExcelImport`/styles copied from VendorGate; one `RecordModal` form for every record (`components/RecordForm.tsx`); field lists in `components/ClientForms.tsx`; one `ObligationTable` / `ObligationModal` / `EventModal` (`components/Obligations.tsx`) for dashboard, calendar and client tab; labels in `lib/format.ts`; product name only in `components/Brand.tsx`.

- **Meetings**: `services/meetings.ts` (schedule, agenda, attendance, held → calendar + filings via services/obligations.ts, minutes); rules in `meetings/checks.ts`, wording in `meetings/templates.ts`; documented in `docs/meetings.md`. Web: `components/Meetings.tsx` (list, schedule) shared by the Meetings page and the client's Meetings tab; `pages/MeetingDetail.tsx`, `pages/MeetingPrint.tsx`.
- **Picking clients**: `components/ClientPicker.tsx` (type-to-search by name/CIN over `/clients/lookup`, chips) — use it wherever companies are chosen, never a full list. Client users are managed from the client's *Client users* tab (`components/ClientUsers.tsx`) or Administration → Users.
- **Platform / sign-up / trial**: `services/platform.ts` — `signUp`, `accessState` (TRIAL / ACTIVE / TRIAL_ENDED / PAYMENT_DUE / SUSPENDED / PENDING_APPROVAL), `assertClientCapacity`, platform settings (approval switch, trial days, trial client limit), console actions. Read-only enforcement in `requireWritable` (auth/session.ts). Platform admins = emails in `PLATFORM_ADMINS`. Email via `lib/mailer.ts` (SMTP_* env; logs when unset).
- **Filing workflow**: stages once in `services/stages.ts` (TODO → DATA → DRAFTED → REVIEW → CLIENT → READY → FILED → APPROVED, plus RESUBMIT / NA; status derived from stage). Every move goes through `services/workflow.ts` (`MOVES`, `allowed` = maker-checker + client approval, `move` with stage guard + `obligation_events`). Firm switches in `lib/settings.ts` (`settingsOf`: requireReview, requireClientApproval, reminder days). Documented in `docs/workflow.md`. Web: `FilingModal` inside `components/Obligations.tsx`.
- **Documents**: `lib/storage.ts` (driver: db bytea by default, `STORAGE=s3` + S3_* env); routes `routes/files.ts`; one `components/Attachments.tsx` for clients (Documents tab), filings and meetings.
- **Reminders**: `services/reminders.ts` builds one digest per user (due on reminder days, overdue, waiting for review/approval, DSC expiry, minutes) and logs to `reminder_log` so a day is sent once; daily job 03:00 UTC in `jobs.ts`; preview on Administration → Settings.
- **Reading documents** (AI fills forms, a person checks): document kinds as data in `server/src/extract/doctypes.ts`; `extract/reader.ts` (Claude, forced tool call; `EXTRACT_DRIVER=mock` uses `extract/fixtures.ts`; DSC .cer read directly); pure `extract/normalise.ts` (reuses validators; tested); `services/extract.ts` applies only through services/clients.ts. Web: one `components/DocumentReader.tsx` (`ReadDocument`, `DscReader`) and one `components/DropZone.tsx` for every file drop. Board papers → event filings: `proposeEvents` in normalise.ts (matches people and the calendar), applied via `addEvent`. Documented in `docs/documents.md`.
- **Pre-filing check**: pure `server/src/review/checks.ts` (`recordChecks` against records, `compareDraft` of AI-read draft values — comparing is code); `services/review.ts` (context, stored `filing_checks`, history entry); web `components/ReviewCheck.tsx` in `FilingModal`. Add a check = a few lines in checks.ts + a test. Documented in `docs/workflow.md`.
- **MCA form data packs**: form specs as data in `server/src/eforms/forms.ts` (parts → fields: from records, client profile `clients.profile`, or this filing `obligations.form_data`); pure `eforms/build.ts`; `services/eforms.ts` (context incl. meetings & attendance, save inputs, Excel); web `pages/FormPack.tsx` (`/filings/:id/form`). Documented in `docs/eforms.md`.
- **Chrome extension (MCA form filler)**: `extension/` (MV3 side panel `panel.js`, page script `content.js`, pure label matching `lib/match.js` — shared with tests); API `routes/ext.ts` behind `requireExtension` (Bearer `cdx_` tokens, `api_tokens`, read-only); connection codes + download on web `pages/Extension.tsx`. Field aliases for matching live in `eforms/forms.ts`. Harness in `extension-test/`. Documented in `docs/extension.md`.
- **Help**: the manual is `help/manual.md` (one source; images in `web/public/help/`); pure `server/src/help/manual.ts` (sections, search, FAQ match, page → section); `help/assistant.ts` (Claude answers only from the manual; search fallback); `services/help.ts` (daily limit, `help_questions` log, ratings); routes `routes/help.ts`. Web: one `components/HelpAssistant.tsx` (drawer from the **?** button in `Shell.tsx`, and `pages/Help.tsx`), one `components/Markdown.tsx`. When a screen changes, update the manual. Documented in `docs/help.md`.

## Commands
`npm run dev` · `npm test` (engine) · `npx tsx server/scripts/smoke.ts` and `smoke-signup.ts`, `smoke-rules.ts`, `smoke-meetings.ts`, `smoke-workflow.ts`, `smoke-extract.ts`, `smoke-review.ts`, `smoke-eforms.ts`, `smoke-ext.ts` (end-to-end, need running API + fresh seed, PLATFORM_ADMINS=admin@demo.in, EXTRACT_DRIVER=mock) · `npm run db:seed` (demo workspace "demo", admin@demo.in / Demo@12345) · `npm run db:generate` after schema changes.
